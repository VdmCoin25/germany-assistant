## 2. Хватит ли данных API для табло

| Элемент табло | Данные | Есть? |
| --- | --- | --- |
| Станция = город | `me.city` или `seeker.city` | да |
| Шаг 1 «Анкета» | `seeker == null` | да |
| Шаг 2 «Проверка» | `seeker.status == "pending"` | да |
| Шаг 3 «Предложения» | `seeker.status == "approved"`, нет приглашений `sent` | да |
| Шаг 4 «Согласие» | в `inbox` есть `kind=offer, status=sent` → «Посадка» | да |
| Шаг 5 «Собеседование» | `status=accepted` = контакты переданы. О самом собеседовании данных нет | частично → предлагаю назвать шаг «Контакт передан» |
| Число новых предложений | количество `inbox` со `status=sent` | да (это «ждут ответа», а не «непрочитанные») |
| Анкету отклонили | `seeker.status == "rejected"` | да, но **причины нет** |
| Время в шапке «ответ до 18:00» | срока проверки в системе нет: модерация ручная, без SLA | **нет**. Обещать «за 24 ч» нельзя, пока админы не договорились |
| «Обновлено 21:01» | API отдаёт только **даты** (`updated`, `published`), без времени | **нет** → нужна правка API: отдавать ISO-время |
| Карточка предложения: город, график, зарплата | в `inbox` есть только `vacancy` (название), `company`, `message` | **нет** → нужно добавить в `describe()` поля вакансии |
| «Проверенный работодатель» | приглашение возможно только от одобренного работодателя | да (выводится из правила) |
| Дождь = ожидание | шаг 2 или шаг 3 без предложений | да |
| Жильё как «маршрут» со статусом | у жилья нет состояния пользователя | **нет** → жильё остаётся обычной ячейкой, без статуса |
| Город с подсказками | в API есть только земли (`LANDS`) | **нет** → нужен список городов (см. п. 5) |
| Черновик анкеты | CloudStorage Telegram, на клиенте | да, бэкенд не нужен |
| Что увидит работодатель | `seeker_public` (без имени и контактов) | да |
| Что получит работодатель при согласии | бот отправляет ему должность, город и ссылку на Telegram (`notify.answered`) | да — текст экрана согласия должен говорить ровно это |

**Минимальные правки бэкенда** (только чтения, без новых таблиц):
1. `GET /api/jobs/me`: в `inbox` добавить `city`, `land`, `employment`, `salary` вакансии; даты отдавать с временем (`created_at` ISO).
2. `seeker_own`: добавить `updated_at` с временем.
3. Отдача новой сборки по `/app-v2` (одна строка в `api.py`).
4. Тест на одинаковые ключи `uk`/`ru` для текстов нового приложения.

Причину отклонения анкеты и срок проверки без решения владельцев не добавляю — это процесс модерации, а не экран.

## 3. TelegramUI — проверено установкой

Пробная сборка Vite в песочнице (`npm`, официальный реестр):

- **Версия:** `@telegram-apps/telegram-ui` **2.1.13**, вышла 14.10.2025. Последний коммит в репозитории — тот же день. **13 месяцев без обновлений** — главный риск.
- **React:** peerDependencies `react ^18.2.0`. React 19 ставится только с `--legacy-peer-deps`, сборка на 19 тяжелее (87 КБ против 64 КБ gzip). → **React 18.3.**
- **Компоненты есть:** `AppRoot, List, Section, Cell, ButtonCell, Placeholder, Button, IconButton, Input, Textarea, Select, Multiselect, Chip, Checkbox, Radio, Switch, SegmentedControl, Tabbar, Badge, Banner, Card, Progress, CircularProgress, Skeleton, Spinner, Snackbar, Modal, Steps, Timeline, Info, Divider, Typography`.
- **Нет:** поиск с подсказками (combobox). `Steps` и `Timeline` есть — на них можно строить «Шаг 2 из 6» и линию маршрута, но вид линии всё равно наш.
- **Шрифт:** системный (`system-ui, -apple-system, Roboto`), веб-шрифтов и CDN нет. CSS — 45 КБ (10 КБ gzip), импорт обязателен.
- **Внутри** тянет `@radix-ui/react-dialog` (через форк `vaul`) и `@floating-ui/react-dom`.

**Размер начального JS (gzip), измерено:**

| Набор | JS | CSS |
| --- | --- | --- |
| React 18 + TelegramUI | 54,5 КБ | 10,4 КБ |
| + `@tma.js/sdk-react` 3.0.23 | 64,5 КБ | 10,4 КБ |

Лимит из задачи — 200 КБ, запас большой. Ariakit ради одного поиска города не беру: подсказки делаю сами на `Input` + `List` с ролями ARIA (`combobox`/`listbox`), ~2 КБ.

## 5. Сборка и выкладка на Render

- В нативных средах Render **Node и npm уже есть** на этапе сборки, в том числе у Python-сервисов (render.com/docs/native-runtimes). Версию закрепляет `NODE_VERSION`.
- **Предложение для `render.yaml`** (не применяю без согласия): `buildCommand: pip install -r requirements.txt && cd webapp && npm ci && npm run build`, `NODE_VERSION=22`. Vite кладёт сборку в `app/webapp/static/v2/`, FastAPI отдаёт её по `/app-v2`. Старое `/` не трогается.
- Сборка на Render добавит ~1 мин к деплою. Бесплатных минут сборки хватает, но это стоит проверить в первый деплой.
- Альтернатива — собирать в GitHub Actions и коммитить готовые файлы. Проще для Render, но сборка в `main` — источник конфликтов с Владиславом. Не рекомендую.
- **Список городов** для подсказок: нужен источник. Вариант — Gemeindeverzeichnis Destatis (лицензия dl-de/by-2-0, нужна атрибуция) — **лицензию проверю до J3**. До этого — свободный ввод + подсказки из земли.

## 6. Два варианта стека

**Вариант 1 — TelegramUI + tma.js SDK (как в задаче)**
- Vite 8 + React 18.3 + TypeScript, `@telegram-apps/telegram-ui` 2.1.13, `@tma.js/sdk-react` 3.0.23.
- Плюсы: готовые сигналы для темы, кнопок, safe area; типы.
- Минусы: две внешние зависимости, обе с риском — TelegramUI не обновлялся 13 месяцев, у SDK скоро 4.0 с другим API. +10 КБ.

**Вариант 2 — TelegramUI + официальный `telegram-web-app.js` (рекомендую)**
- Vite 8 + React 18.3 + TypeScript, `@telegram-apps/telegram-ui` 2.1.13. Вместо SDK — свой тонкий слой (~150 строк): хуки `useTheme`, `useBottomButton`, `useBackButton`, `useCloudStorage`, `useSafeArea`, `useHaptic` поверх `window.Telegram.WebApp`.
- Плюсы: меньше зависимостей (меньше рисков для данных беженцев), API от самого Telegram, не сломается при выходе tma.js 4, −10 КБ. Скрипт `telegram-web-app.js` бот уже использует.
- Минусы: слой пишем и тестируем сами.

В обоих: React 18, свой поиск города, линия маршрута и шапка-табло — наши компоненты на `Steps`/`Timeline` и токенах.
