# Germany Assistant — правила работы с репозиторием

Над ботом работают двое (Вадим — VdmCoin25, Владислав — k-jdev) и Claude.

## Ветки
- `main` — рабочая версия. Каждый коммит в `main` сразу выкатывается на Render и в живой бот.
- Напрямую в `main` не коммитить. Любая задача — отдельная ветка от свежего `main`:
  `feat/<коротко>`, `fix/<коротко>`, `chore/<коротко>`.
- Перед началом работы: `git fetch origin main` и ветка от `origin/main`.
- Готово → pull request в `main`. Сливать, только когда проверка `tests` на GitHub зелёная.
- Слияние — squash (один коммит на задачу), ветку после слияния удалить.
- Если `main` ушёл вперёд и есть конфликты — обновить ветку от `main`, разрешить конфликты, прогнать тесты.

## Перед pull request
- `pytest -q` локально проходит.
- Новые таблицы БД — только через миграцию Alembic в `migrations/versions/`.
- Тексты для пользователей — в `app/i18n/locales/uk.json` и `ru.json` (одинаковые ключи, это проверяет тест).
- Никаких токенов и паролей в коде: только `.env` / переменные окружения Render.

## Важное о продукте
- Юридические и миграционные правила не выдумывать: только со ссылкой на официальный источник и датой проверки.
- Биржа работы: всё публикуется только после одобрения админа; контакты соискателя — только после его согласия.
- Парсинг сайтов вопреки их условиям запрещён.
